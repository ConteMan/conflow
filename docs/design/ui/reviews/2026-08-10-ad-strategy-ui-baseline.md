# 广告策略 UI 基线审计（2026-08-10）

> 结论：当前 React 实现与 2026-07-10 `.pen` 基线都不是单独的最终事实源；本需求以实机采集为现状证据，以 Spec 028 收口行为合同，再同步最终 `.pen` 页面。

## 采集范围

- Pen 内置浏览器：`http://127.0.0.1:19010/#configuration`
- 当前实现：广告位列表、广告位详情、频控策略抽屉
- 设计基线：`014 / Placement Table`、`014 / Placement Detail`、`014 / Frequency Drawer`
- 采集 fixture：3 个广告位、3 个频控、3 个开关、3 个广告单元绑定

## 差距判断

| 区域 | 当前实现保留 | `.pen` 基线保留 | 收口动作 |
|---|---|---|---|
| 配置列表 | 导入、运行校验、搜索、类型筛选、仅看未发布修改 | 桌面信息密度、稳定顶栏与发布状态反馈 | 新设计同时保留操作能力和桌面密度 |
| 广告位详情 | 分区表单、稳定深链、修改摘要、源映射 | 更紧凑的主侧栏层级与风险状态 | 继续独立详情页，统一间距、状态和来源 caption |
| 频控编辑 | 显式启用/关闭、引用广告位列表、删除保护 | 保留列表上下文的 Drawer 模式 | 频控继续 Drawer；策略不用 Drawer |
| 响应式 | 当前约 1032px 已折叠菜单，表格出现内容裁切 | 1440/1280 桌面基线、390 窄屏专门页面 | 校正断点；390 策略只读，桌面承担编辑 |

## 广告策略页面决策

1. 配置区新增「广告策略」tab，设置卡与策略列表同页，避免把单例设置藏进项目设置。
2. 策略编辑使用独立详情页，因为 allowlist、逐广告位继承/覆盖、影响摘要和校验定位需要稳定 URL 与完整横向空间。
3. 详情页以“广告位”为编辑单元：先选择 allowlist，再逐行查看基础频控、覆盖值和最终有效值。
4. 继承、显式关闭、自定义值是三种不同状态，必须以文本和控件状态同时表达。
5. 删除保护与影响摘要消费服务端引用图和 Plan 风险，不在 React 重算。

## 同步顺序

1. Spec 028、Pack schema、OpenAPI 与共享 fixture 先冻结行为。
2. React 基于真实 API 完成桌面主流程。
3. Pen 内置浏览器将真实页面导入审计区，对齐组件、间距和响应式后再更新最终页面。
4. 以 1440、1280、390 三档截图进行双向复核；差距通过 GitHub Issue 跟踪，不在本文维护待办。

## 可复用经验

- 既有项目先“浏览器采集 → 局部导入/对照 → 合同收口 → 实现 → 回灌设计”，比从旧稿或代码单向追齐更可靠。
- 设计稿负责信息层级、状态和布局；OpenAPI/Spec 负责行为；实机截图负责证明当前事实，三者职责不可互换。
- `.pen` 是不可文本合并的设计资产，保持单写者并在一次完整页面收口后再更新，减少无意义漂移。
